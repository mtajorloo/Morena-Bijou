Project SHANSI `01a0c8cc-6459-76dd-9217-57c65db6df53`. Scope is Phase A of [`OPERATIONS_AND_ADMIN.md`](OPERATIONS_AND_ADMIN.md): real backend, real accounts, admin back office, play credits only.

Phase A: turn SHANSI from a browser-only demo into a real app with a real backend, real accounts and an admin back office, still on play credits (no real money yet). Keep the current v3 frontend design exactly as it is (same components, CSS, media, screens and counter animation); only change where the data comes from and add the pages listed below. Do not ask clarifying questions; every decision here is final. Build in this order and deploy the draft at the end.

1. BACKEND (Motoko, stable memory, upgrade-safe)
- Accounts keyed by principal: principal, optional email, displayName, createdAt, status (active | frozen | closed), role (player | support | finance | owner), selfExcludedUntil (optional), support notes.
- Ledger: append-only entries {id, principal, kind: freeCredit | ticket | prize | adjustment | withdrawalHold | withdrawalPaid, amount in whole credits (1 credit = 1 play USDT), drawId (optional), reference, createdAt, actor}. Balances are derived from the ledger (cached), never edited directly.
- Draws: {id, scheduledAt (top of the hour UTC), state: open | closed | drawn, commitHash, seed (revealed only after the draw), rawRand, ticketListHash, result "0000" to "9999", ticketsSold, poolCredits, jackpotBefore, jackpotAfter, payouts per tier, winners}. A canister timer closes sales at :59:30 UTC (compute ticketListHash = sha256 of the sorted ticket list) and draws at :00:00 UTC: result = sha256(seed || rawRand || ticketListHash) mod 10000, where rawRand comes from the management canister raw_rand. Immediately after a draw, create the next draw and publish the commit hash sha256(nextSeed). If a tick was missed, catch up on the next timer or call.
- Tickets: {id, drawId, principal, number, createdAt}; cost 1 credit; max 50 per player per draw (configurable); rejected when sales are closed or paused, balance is insufficient, or the account is frozen.
- Prize rules exactly as today: match from the right; 4 digits = jackpot shared among exact winners; last 3 = 40 credits; last 2 = 5; last 1 = 1 credit. Jackpot = 50% of each draw's ticket sales added to the pool plus rollover when nobody hits it; floor 500 credits (house-funded). Daily Drop: for the 00:00 UTC draw, if there is no exact match the closest ticket(s) share the jackpot. Prizes are credited to the ledger inside the draw call.
- Play credits: claimDailyCredits gives each player N free credits once per UTC day (config, default 10). No deposits and no withdrawals in this phase. Still implement a withdrawal request state machine (requested -> approved -> paid | rejected) with an admin queue for later; the player-facing withdraw action stays hidden while config.withdrawalsEnabled is false.
- Config (versioned; changes take effect from the next draw, never mid-draw): ticketPrice 1, tiers as above, jackpotShare 50%, jackpotFloor 500, salesCloseOffsetSeconds 30, maxTicketsPerDraw 50, dailyFreeCredits 10, withdrawalsEnabled false, salesPaused false, maintenanceMode false.
- Roles and audit: role checks on every admin method; every admin action appended to an audit log {id, actor, action, target, before, after, at}. Bootstrapping: the first authenticated principal that calls claimOwner while no owner exists becomes owner; afterwards only the owner grants or revokes roles. Owner-only runDrawNow performs the scheduled draw early (closing sales first) and logs it.
- Public queries, no login needed: current draw with scheduledAt and state, jackpot, last 24 draws with all fairness fields, config. Authenticated queries: my balance, my tickets for the current draw, my ledger, my payouts for a given draw.
- Backend unit tests for right-to-left matching, tier payouts, jackpot rollover and floor, Daily Drop, sales-close rejection.
